# Архитектура

Бот (maxapi, MAX) <-> Backend (FastAPI, БД) <-> Mini app (React, открывается кнопкой в чате бота)

Основной поток заказа:
1. Пользователь жмёт кнопку "Каталог" в чате бота -> открывается mini app (mini app привязан к
   боту в кабинете MAX для партнёров, URL там же и настраивается, а не передаётся из кода бота).
2. Mini app обращается к backend за списком букетов, авторизуясь через WebAppData
   (строка `window.WebApp.initData`, полученная через MAX Bridge).
3. Backend валидирует подпись WebAppData (HMAC-SHA256 на основе токена бота) и достаёт из неё
   данные пользователя MAX.
4. Пользователь собирает корзину, указывает адрес и время доставки, оплачивает.
5. Mini app отправляет заказ напрямую в backend (POST /orders) — в отличие от Telegram, у MAX
   нет моста sendData обратно в бота, поэтому вся логика заказа идёт через backend.
6. Backend создаёт заказ и дальше уведомляет пользователя через бота (bot/app/services/notifications.py)
   о смене статусов: принят, собран, курьер выехал, доставлен.
7. Админ/CRM (admin-panel) видит все заказы и меняет статусы, курьера.
